4  Chapter of choice: The R Package gtrendsR

The package gtrendsR provides an R interface to the Google Trends API. It enables us to download and analyze data about how frequently certain terms are searched on Google. Search interest can be studied across different regions, time windows, and categories, which makes the package useful for projects that aim to investigate public attention toward specific topics.

4.1 Core Function

The core function of the package is: gtrends(), which sends queries to the Google Trends API and returns the result.

4.2 Main Parameters

Some of the most relevant arguments that we can specify in gtrends() are:

  • keyword: One or more search terms (character vector).

  • geo: Geographic scope of the search. Examples:

    • "US" → United States
    • "DE" → Germany
    • "" → worldwide

  • time: The time frame of interest. Possible values include:

    • "now 7-d" → past 7 days
    • "today 12-m" → past 12 months
    • "YYYY-MM-DD YYYY-MM-DD" → custom date range

  • gprop: The Google search property (some examples):

    • "web" (default)
    • "news"
    • "images"

  • category: Restricts results to a specific category (e.g., "67" for Finance).

4.3 Structure of the Results

A typical call to gtrends() returns a list of data frames. The most commonly used components are:

  • interest_over_time
    Time series of relative search interest (scaled 0–100) for the chosen keyword(s).

  • interest_by_country
    Aggregated search interest at the country level.

  • interest_by_region
    Regional breakdown (e.g., states, cities, DMA) depending on geo parameter.

  • related_topics
    Topics that are often searched together with the given keyword(s).

4.4 Summary

In summary, the package gtrendsR is a powerful tool that allows us importing Google Trends data directly into R.
With gtrendsR, we can:

  • Track search interest over time,
  • Compare search intensity across regions, and
  • Explore related queries and topics that frequently appear alongside our keywords.

4.5 Interpretating Google Trend Data

The values from 0 to 100 on Google Trends represent normalized, relative search interest, not an absolute number of search queries. The value 100 indicates the peak popularity of a search term in a selected time period and region. All other values are relative to this peak value. For example, a value of 0 means that there is insufficient data or that the search term has a very low search volume.

How the numbers work:

  1. Normalization: Google Trends normalizes the data on a scale from 0 to 100 to represent search interest in relation to all search queries.
  2. Relative values: The values are not absolute quantities, but show how often a term was searched for in comparison to its own peak.
  3. The number 100: This represents the time or region when a search term reached its peak popularity.
  4. The number 0: This means that there was insufficient data for the search term at that time or in that region.
  5. Example: If a search term receives a 50, this means that search interest was only half as high as the peak value, which is 100.
  6. Keep in mind: If you combine a search with a very popular and a rather rare search term, the rare search term will get (very) low numbers. But when you are only searching for the rare term it will also get a 100 once, namely for the one day when it was most often searched for.

4.6.2 Load data

Google is restricting the download-limit of Google Trends data. Sometimes already after one download, it is not possible to make another download. As the behavior is - also based on comments of other users - very unpredictable, we saved successful downloads as RData objects and load the data whenever needed.

4.6.3 Prepare the interest_by_country data in gtrends

The interest_by_country dataframe, which contains geographic search data, required two steps before it could be used in analysis.

First, We have to adjust some location iso-codes so they fit to the map data. Second, the main metric ‘hits’ contains ‘<1’, which makes the column a character string. We replace <1 and NA with 0 and set the column to numeric.

Show/Hide the code 
country_data_Tesla <- res$interest_by_country %>%
  mutate(
    iso2c = countrycode(location, "country.name", "iso2c",
                        custom_match = c("Kosovo" = "XK")),
    iso3c = countrycode(location, "country.name", "iso3c",
                        custom_match = c("Kosovo" = "XKX")),
    hits = case_when(
      hits == "<1" ~ 0,
      is.na(hits) ~ 0,
      TRUE ~ as.numeric(hits)
      )) %>%
  select(iso2c, iso3c, country = location, hits, keyword) %>%
  arrange(desc(hits))

4.6.4 Load and prepare the map data using ne_countries function from the rnaturalearth package.

Some missings can be replaced with values from other columns (e.g. France with its overseas regions was a bit of an issue). Then the data is left joined with the prepared Google Trends data.

Show/Hide the code 
## Get world map data
world_sf <- ne_countries(scale = "medium", returnclass = "sf") %>% 
  mutate(
    iso_a2 = if_else(iso_a2 == "" | is.na(iso_a2) | iso_a2 == "-99", iso_a2_eh, iso_a2),
    iso_a3 = if_else(iso_a3 == "" | is.na(iso_a3) | iso_a3 == "-99", iso_a3_eh, iso_a3),
    iso_n3 = if_else(iso_n3 == "" | is.na(iso_n3) | iso_n3 == "-99", iso_n3_eh, iso_n3))

## Join by ISO3
world_trends <- world_sf %>%
  left_join(country_data_Tesla, by = c("iso_a3" = "iso3c"))
